1. System Overview & Architecture

The Enterprise Inventory and Order Management System is an enterprise-grade platform designed for centralized stock tracking across multiple physical warehouses, supplier lifecycle administration, order fulfillment with ACID transactional stock reservations, and automated audit logging.

High-Level System Topology

Role-Based Access Control (RBAC) Matrix

Role Access Scope Permitted Operations
Admin Full System Administration Manage all users, view audit logs, create/update/delete products, configure warehouses, initiate transfers & adjustments, override order states.
WarehouseManager Warehouse & Stock Operations Perform physical stock adjustments, transfer stock between warehouses, manage product catalog (Create/Update), update order status to Processing/Completed.
SalesRepresentative Sales & Customer Orders Browse live product inventory across warehouses, create customer sales orders with real-time stock deduction, track order fulfillment, cancel orders.
Auditor Compliance & Quality Control Read-only inspection of inventory valuation, warehouse levels, stock movement transactions, and full immutable system audit logs.

2.1 Authentication & User Endpoints

POST /api/auth/login Anonymous
Validates credentials using BCrypt hash comparison, records user login audit log, and issues a 12-hour signed JWT token with identity and role claims.
Request Body: 
{
  "username": "admin",
  "password": "Password123!"
}
Response (200 OK): 
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresAt": "2026-10-23T23:59:59Z",
  "user": {
    "id": 1,
    "username": "admin",
    "email": "admin@enterprise.com",
    "fullName": "Enterprise Administrator",
    "role": "Admin",
    "isActive": true
  }
}
GET /api/auth/me Authenticated
Returns the authenticated user profile based on the JWT bearer token claims.
Response (200 OK): Returns UserDto object.
GET /api/auth/users Admin Auditor
Retrieves list of all registered system users and assigned roles.

2.4 Multi-Warehouse Inventory & Stock Movement Endpoints

Method Route Authorized Roles Description
GET /api/inventory All Authenticated Paginated inventory matrix across warehouses. Supports lowStockOnly=true filter.
GET /api/inventory/low-stock-alerts All Authenticated Returns all inventory records where QuantityOnHand <= ReorderPoint.
POST /api/inventory/adjust Admin WarehouseMgr Adjust physical stock with reason audit (Cycle count, Damaged, Replenishment).
POST /api/inventory/transfer Admin WarehouseMgr ACID inter-warehouse transfer: atomically deducts source warehouse and credits target warehouse.

ACID Concurrency Guarantee: Inventory transfers execute within an explicit database transaction isolation scope. If the source warehouse lacks sufficient available stock or any database failure occurs, the entire transaction is rolled back with zero partial deduction.

3.2 Page-by-Page Specifications & Interaction Workflows

1. Login Page (/login)

  • Purpose: Authenticate user and initialize secure session.
  • Features: Form validation, quick-fill role buttons (Admin, Warehouse Mgr, Sales Rep, Auditor), authentication progress indicator.
  • Post-Login Navigation: On HTTP 200, saves token to localStorage, populates user signal in AuthService, and redirects immediately to /dashboard.

2. Operations Dashboard (/dashboard)

  • Purpose: Executive command center for inventory status, predictive alerts, and operational health.
  • KPI Cards: Total Active Products, Inventory Asset Valuation ($), Low-Stock Items Count, Active Warehouses Count, Cumulative Sales Revenue ($).
  • Phase 2 AI Predictive Card: Surfaces critical stockout risks (<3 days), restock recommended counts, overstocked items, and exact tied-up carrying capital ($).
  • Quick Actions: Primary triggers for + New Order, Adjust Stock, and Explore Restock Recommendations.

3. Products Catalog (/products)

  • Purpose: Central product registry and AI catalog hygiene control.
  • Interactions: Real-time text search (SKU/Title), Category dropdown filter, Supplier dropdown filter.
  • Phase 2 AI Catalog Deduplication: Global 1-click catalog scanner identifying duplicate SKUs, Jaccard token overlap, and category misclassifications with overall Quality Score.
  • Phase 2 AI Auto-Pick: Natural language semantic classifier suggests optimum product category automatically when creating/editing products.
  • Modals: "Add Product", "Edit Product", and "AI Catalog Deduplication Audit" dialogs with live validation.

4. Multi-Warehouse Inventory (/inventory)

  • Purpose: Physical stock visibility, AI predictive replenishment, and inter-warehouse movement orchestration.
  • Phase 2 AI Demand Forecasting Tab: Analyzes 30-day order velocity to compute Dynamic Safety Stock (SS = ⌈1.65 × √(Lead Time) × max(1, Daily Burn × 0.7)⌉) and Dynamic Reorder Point (ROP = (Daily Burn × Lead Time) + SS).
  • Phase 2 Restock PO Generator: 1-click batch Purchase Order builder with item breakdown, estimated costs, lead times, and instant replenishment execution.
  • Phase 2 Overstock & Dead Stock View: Identifies capital tied up in excess items (>60 days runway) with 1-click rebalancing transfer actions.
  • Warehouse Selector: Filter stock and forecasts by physical distribution facility.
  • Stock Adjustment & Transfer Modals: Allows warehouse staff to modify quantities or transfer inventory with ACID transactional atomicity.
  • Movement Ledger: Historical log of every stock alteration with timestamp, delta, and operating user.

5. Order Management & Fulfillment (/orders)

  • Purpose: Sales order intake, AI invoice/PO document processing, and delivery tracking.
  • Phase 1 AI Document Ingestion: Multimodal OCR scanner supporting PDF, PNG, and invoice images with automated line-item token parsing and catalog SKU matching.
  • Status Workflow: Visual pill badges indicate state: Pending → Processing → Completed or Cancelled.
  • Order Creation Dialog: Dynamic line-item builder with customer details. Automatically verifies warehouse stock levels before submission.
  • Order Cancellation Flow: Prompts for cancellation reason and triggers the automatic inventory restock routine on the backend.

6. Suppliers Directory & Autonomous Procurement (/suppliers)

  • Purpose: Vendor relationship management, reliability evaluation, and autonomous replenishment policies.
  • Phase 3 AI Supplier Scorecards: Evaluates historical lead-time variance (±days), on-time delivery probability, and assigns vendor tiers (🥇 Gold Preferred, 🥈 Silver, ⚠️ High Risk).
  • Phase 3 Failover Routing: Recommends alternate secondary vendors to mitigate supply-chain disruptions.
  • Phase 3 Autonomous Procurement Policies: Interactive self-governing replenishment rules that automatically draft purchase orders when runway breaches safety boundaries (≤ threshold days, PO cap limits).
  • Directory Actions: Add new vendor profiles, edit terms, and filter supplied products.

7. System Audit Trail & AI Shrinkage Radar (/audit)

  • Purpose: Compliance oversight, regulatory traceability, and automated shrinkage detection (restricted to Admin, Auditor, and Warehouse Managers).
  • Phase 3 AI Shrinkage & Anomaly Radar: Unsupervised heuristic anomaly scanner evaluating off-hours stock adjustments, abnormal cancellations, rapid shrinkage spikes, and transfer discrepancies.
  • Executive Risk Metrics: Overall Network Risk level, Active Flagged Anomalies, Critical Exposure ($), and Discrepancy Units.
  • 1-Click Investigation & Resolution: In-app supervisor audit modal allowing warehouse supervisors to verify physical counts, record resolution notes, and resolve security flags.
  • Compliance Audit Logs Tab: Immutable record of user actions, payload diffs, and IP addresses.

8. Global Enterprise AI Copilot (Phase 1, 2 & 3 Autonomous AI)

  • Purpose: Conversational intelligence assistant accessible across all screens via slide-out drawer.
  • Capabilities: Answers plain-English inquiries about shrinkage anomalies, supplier reliability scorecards, autonomous replenishment, predictive demand forecasting, dynamic restock runway, overstock capital, warehouse valuations, and catalog deduplication.
  • Deep Navigation: Generates interactive action buttons directly navigating to relevant application views and opening workflows (e.g., /audit?tab=anomalies, /suppliers?view=ai-scorecard, /inventory?tab=forecast).

4. Error Handling & Architectural Standards

Standard RFC 9110 Error Response Structure

All HTTP exception scenarios (validation faults, missing resources, unauthorized attempts, concurrency conflicts) return a structured JSON response managed by the centralized ExceptionHandlingMiddleware: 

{
  "status": 400,
  "title": "Insufficient Stock",
  "detail": "Requested 50 units of Wireless Keyboard, but only 12 are available in Central Warehouse.",
  "errors": {
    "productId": 4,
    "productName": "Wireless Keyboard",
    "availableQuantity": 12,
    "requestedQuantity": 50
  },
  "timestamp": "2026-10-23T06:45:00.123Z"
}

HTTP Status Code Mapping

Status Code Title Trigger Scenario
200 OK Success Query succeeded or entity updated.
201 Created Resource Created Product, category, order, or supplier created with Location header.
204 No Content No Content Deletion completed successfully or preflight response.
400 Bad Request Validation / Business Rule Insufficient inventory, invalid SKU, duplicate identifier.
401 Unauthorized Authentication Missing Missing, expired, or invalid JWT Bearer token.
403 Forbidden Insufficient Role Authenticated user does not possess required role claim.
404 Not Found Resource Not Found Target entity ID does not exist in the database.
409 Conflict Concurrency Conflict Simultaneous modification detected on same inventory row.
Security Note: Passwords are never stored or logged in plain text. All user passwords are salted and hashed using BCrypt. JWT secret keys are stored securely in backend configuration with minimum 256-bit cryptographic strength.
